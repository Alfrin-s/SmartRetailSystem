Smart Retail Inventory & Billing System

Complete Technical Architecture, Function Guide & Viva Examination Manual

A full-scale desktop Point-of-Sale (POS) and inventory management platform built entirely with pure Java (JDK 17+), Java Swing, JDBC, and MySQL 8.x, enforcing MVC separation, ACID transactions, and Role-Based Access Control.

LanguageJava (JDK 17+)
UI FrameworkJava Swing & Java 2D
Database EngineMySQL 8.x (JDBC)
ArchitectureStrict MVC & DAO

1. System Overview & MVC Architecture

The application follows the industry-standard Model-View-Controller (MVC) architectural pattern paired with the Data Access Object (DAO) design pattern. This architecture completely decouples visual presentation from business logic and database persistence, preventing spaghetti code and eliminating SQL queries from Swing UI action listeners.

Architectural Layer Flow

User Interaction Flow:

[ User / Cashier / Admin ]
    │ (Mouse clicks, barcode scanning, keyboard input)
    ▼
VIEW LAYER (Java Swing: Frames, Panels, Tables, Dialogs)
    │ (Fires Controller action methods; receives rendered DTO models)
    ▼
CONTROLLER LAYER (Orchestrators: BillingController, ProductController, etc.)
    │ (Executes validation, orchestrates transactions, calculates math)
    ▼
MODEL LAYER (Pure POJOs: Product, Bill, BillItem, User, Inventory)
    │ (Represents state and domain business constraints)
    ▼
DAO LAYER (Data Access Objects: BillDAO, ProductDAO, UserDAO)
    │ (PreparedStatement queries, connection lifecycle, ACID rollback)
    ▼
DATABASE ENGINE (MySQL 8.x on Port 3306 via Connector/J)

3. How Each Core Function Operates (Java Workflows)

1. Self-Healing Bootstrapping & Automatic Schema Setup

When Main.main() executes, it triggers DatabaseConnection.initializeDatabase(). The method connects to MySQL root (jdbc:mysql://localhost:3306/) without targeting a database name. It executes CREATE DATABASE IF NOT EXISTS smart_retail, switches the JDBC connection URL to jdbc:mysql://localhost:3306/smart_retail, and builds tables from resources/schema.sql. If the tables are newly initialized, it inserts default administrative credentials and sample catalog items.

2. Role-Based Access Control (RBAC) Routing

Upon submitting credentials in LoginFrame, LoginController.handleLogin() calls UserDAO.authenticate(user, pass). If valid, the returned User instance is inspected for role authorization. If ADMIN, the full AdminDashboard loads; if CASHIER, the restricted CashierDashboard launches. Administrative buttons and navigation panels are not rendered for cashier accounts, enforcing defense-in-depth.

3. POS Cart Operations & Real-time Tax Mathematics

When a barcode is entered or a product is selected in BillingPanel, BillingController.addItemToCart() queries the active catalog. If currentStock < requestedQuantity, an error dialog blocks addition. Otherwise, the item is added to the cart's DefaultTableModel. On every modification, calculateTotals() executes: 

Subtotal    = Σ (selling_price × quantity)
Tax (8% GST) = Subtotal × 0.08
Grand Total = Subtotal + Tax

4. ACID Transaction Checkout with Rollback Protection

The most critical method in the system is BillDAO.createBillWithItems(). It executes all checkout steps within an explicit atomic transaction: 

Connection conn = DatabaseConnection.getConnection();
conn.setAutoCommit(false); // Enable ACID manual transaction mode
try {
    // Phase 1: Re-verify stock lock for every item
    for (BillItem item : bill.getItems()) {
        int liveStock = queryCurrentStock(conn, item.getProductId());
        if (liveStock < item.getQuantity()) {
            throw new SQLException("Insufficient stock: " + item.getProductName());
        }
    }
    // Phase 2: Insert invoice header into `bills`
    int billId = executeInsertBill(conn, bill);

    // Phase 3: Insert items into `bill_items` and deduct product inventory
    for (BillItem item : bill.getItems()) {
        executeInsertBillItem(conn, billId, item);
        executeDecrementStock(conn, item.getProductId(), item.getQuantity());
    }

    conn.commit(); // Transaction succeeds: all modifications applied simultaneously
} catch (Exception ex) {
    conn.rollback(); // Transaction failed: every insert and stock deduction is completely undone!
    throw ex;
} finally {
    conn.setAutoCommit(true); // Restore default connection state
}

5. Custom Java 2D Graphics Engine (Sales Bar Chart)

Rather than requiring heavy external libraries like JFreeChart, SalesBarChartPanel extends JPanel and overrides paintComponent(Graphics g). It casts to Graphics2D, turns on RenderingHints.KEY_ANTIALIASING, determines the highest sales value in the dataset, dynamically computes coordinate scaling ratios, draws the axes and grid lines, and renders vertical rectangles colored with #C44900 (Rust) and #183A37 (Pine) with numeric text tags centered above each bar.

4. Comprehensive Viva Examination Questions & Answers

Category 1: Object-Oriented Programming (OOP) Principles

How is Encapsulation demonstrated in this project?
Encapsulation is implemented by keeping all class member variables private across domain models (e.g., Product, User, Bill) and providing controlled access via public getters and setters. Setters enforce validation logic—for example, Product.setSellingPrice(double price) checks that the price is strictly positive, preventing invalid state mutations.
Where is Inheritance used, and what architectural benefit does it provide?
Inheritance is used in two key hierarchies:
  • BaseEntity: Inherited by User, Product, Bill, and BillItem. It provides shared fields (id, createdAt, updatedAt) and standardizes lifecycle metadata.
  • BaseDAO: Inherited by UserDAO, ProductDAO, BillDAO, and ReportDAO. It provides centralized connection management and safe resource teardown methods (close()).
This avoids code duplication and enforces structural consistency across the application.
How does your project use Polymorphism?
Polymorphism is demonstrated via the Strategy Pattern in ReceiptExporter. The interface defines File export(Bill bill, File dir), which is implemented polymorphically by TextExporter and PdfExporter. The calling view invokes the shared interface method without needing to know which exporter format is active. Polymorphism is also utilized in StockStatusCellRenderer, which overrides Swing's getTableCellRendererComponent() to dynamically customize cell styling based on row data.
How is Abstraction implemented in the persistence layer?
Abstraction hides complex low-level details. The View and Controller layers do not know whether the system uses MySQL, Oracle, or files; they simply interact with DAO abstract contracts like productDAO.findById(id). All JDBC connections, SQL syntax, driver loading, and ResultSet parsing are abstracted inside the DAO layer.
Why did you use the MVC pattern instead of placing database queries directly inside button action listeners?
Putting SQL queries inside Swing event listeners couples presentation directly with data storage, making the system difficult to maintain, test, or update. MVC enforces Separation of Concerns:
  • View only renders GUI elements and captures user gestures.
  • Controller processes logic, enforces validation, and handles navigation.
  • Model holds state and business constraints.
  • DAO manages data persistence.
This modularity allows modifying the database schema or swapping the UI without breaking business logic.

Category 2: Database, JDBC & ACID Transactions

What are ACID properties, and how does your project guarantee them?
ACID ensures reliable database transaction processing:
  • Atomicity: All-or-nothing execution. In BillDAO.createBillWithItems(), inserting the bill header, adding cart line items, and deducting inventory stock happen together. If any operation fails, conn.rollback() reverts all changes.
  • Consistency: Database constraints (foreign keys, non-negative stock checks) are preserved before and after each transaction.
  • Isolation: MySQL's InnoDB engine ensures concurrent transactions execute independently without dirty reads.
  • Durability: Once conn.commit() completes, the transaction is written to MySQL's redo log and persists across power failures or crashes.
Why is conn.setAutoCommit(false) required in billing checkout?
By default, JDBC operates in auto-commit mode (every individual SQL statement commits immediately). If the bill header were inserted and the system crashed before stock deduction, inventory counts would be corrupted. Calling conn.setAutoCommit(false) groups all operations into a single logical transaction, ensuring manual control over commit() or rollback().
How does your code prevent SQL Injection attacks?
Every query throughout all DAOs strictly utilizes java.sql.PreparedStatement with parameterized placeholders (?). User input is never concatenated directly into SQL strings. The JDBC driver treats inputs as literal data values rather than executable SQL commands, neutralizing injection attempts.
Explain the database schema and foreign key relationships.
The relational schema consists of 4 core tables:
  • users: Primary key id. Stores authentication and roles.
  • products: Primary key id, unique barcode. Stores prices and inventory quantities.
  • bills: Primary key id, unique bill_number, foreign key cashier_id REFERENCES users(id).
  • bill_items: Primary key id, foreign key bill_id REFERENCES bills(id) ON DELETE CASCADE, foreign key product_id REFERENCES products(id).
How does the application handle database creation if MySQL is fresh?
DatabaseConnection.java uses a two-phase connection strategy. It first connects without a database name (jdbc:mysql://localhost:3306/) to execute CREATE DATABASE IF NOT EXISTS smart_retail. It then connects directly to smart_retail and executes table creation scripts and initial seed data if the tables are empty.

Category 3: Java Swing, UI & Event Handling

What is the Event Dispatch Thread (EDT) and why is SwingUtilities.invokeLater() used?
Java Swing is single-threaded and not thread-safe. All component creation, updates, and event listeners must run on the Event Dispatch Thread (EDT). SwingUtilities.invokeLater() places the UI initialization runnable at the end of the AWT event queue, preventing race conditions, UI freezing, and visual rendering glitches.
How did you create the custom 2D Bar Chart without external libraries?
In SalesBarChartPanel, the standard paintComponent(Graphics g) method was overridden. The Graphics object is cast to Graphics2D to enable anti-aliasing. The panel calculates the maximum revenue among the data points, normalizes each bar's height relative to the panel's pixel height, draws coordinate grid lines, and renders colored rectangles for each date using the system's Rust and Pine palette.
How does StockStatusCellRenderer work for table status badges?
It extends DefaultTableCellRenderer. During table painting, Swing invokes getTableCellRendererComponent() for every cell. The renderer inspects the stock quantity: if qty <= 0, it renders an "OUT OF STOCK" badge in soft red; if qty <= minAlert, it renders "LOW STOCK" in amber; otherwise, it renders "OK" in green with rounded borders and bold text.
Which layout managers are used and why?
A combination of layouts is used based on view requirements:
  • BorderLayout: Used for dashboard roots (Top header in NORTH, Navigation in WEST, Main work area in CENTER).
  • CardLayout: Used in AdminDashboard to switch between panels (Dashboard, Products, Billing, Inventory, Reports) without creating and destroying frames.
  • GridBagLayout: Used for forms, login dialogs, and detail cards where precise column alignment and responsive resizing are required.

Category 4: Security, Business Logic & Edge Cases

How is Role-Based Access Control (RBAC) enforced in the application?
When an operator logs in, their role (ADMIN or CASHIER) is stored in the active session. If the user is a cashier, they are routed to CashierDashboard, which only renders the billing screen. Administrative navigation panels (Products, Stock adjustments, Staff management, Financial reports) are not instantiated for cashiers, preventing unauthorized access.
What happens if a cashier tries to sell more items than available in stock?
The application protects against this at two independent levels:
  1. UI Level: BillingController.addItemToCart() checks if requestedQuantity > availableStock. If so, it alerts the cashier immediately and prevents cart insertion.
  2. Database Level: Inside BillDAO.createBillWithItems(), before executing inserts, a live stock query re-verifies inventory. If stock is insufficient, it throws an exception and rolls back the transaction.
How are edge cases like negative product prices or empty inputs handled?
ValidationUtil.java validates all inputs before persistence:
  • Prices must parse to positive doubles (> 0).
  • Quantities must be positive integers.
  • Barcodes must be non-empty alphanumeric strings.
  • Customer phone numbers are validated against standard format patterns.
Any validation error displays a user-friendly message and leaves the database untouched.
How does the PDF Receipt Exporter work without iText or Apache PDFBox?
ReceiptExporter.PdfExporter writes directly to a FileOutputStream using standard PDF 1.4 specification stream syntax. It outputs the standard PDF header (%PDF-1.4), Catalog object, Pages tree, Font dictionary (standard Type 1 Helvetica), and a text stream (BT ... ET) containing invoice details and cross-reference tables (xref). This creates valid, printable PDF receipts with zero external JAR dependencies.
What future enhancements would you suggest for this system?
Potential production enhancements include:
  • Migrating to password hashing with bcrypt or PBKDF2 with salting.
  • Integrating a hardware ESC/POS thermal receipt printer driver via serial/USB.
  • Adding barcode generation (Code128 / QR codes) for in-store printing.
  • Adding payment gateway APIs (e.g. UPI dynamic QR code display at checkout).
